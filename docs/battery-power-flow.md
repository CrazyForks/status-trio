# 电池面板功率流向与高能耗应用

在“设置 → 电池显示 → 电池面板功率流向”中独立选择：

- **充电器输入**：当前进入 Mac 的直流功率，默认关闭。
- **充入电池**：电池正在吸收的功率，默认开启；已停止充电时显示 0 W。
- **系统供电**：整机负载的功率估算，默认开启。
- **高能耗应用**：显示最近采样中较活跃的最多五个应用名称，默认关闭，不显示应用瓦数。

这些选项作用于电池弹出面板。菜单栏和 Dock 图标继续共用现有图标设置与渲染场景。

## 功率数据与图示

优先读取已有 AppleSMC 只读通道：PSTR（整机）、PDTR（适配器输入），以及 Apple Silicon 上的 B0AC/B0AV（电池电流、电压）。一次刷新共用一个短暂连接，只访问固定键，不扫描或写入 SMC。Apple Silicon 整数电池传感器的 mA/mV 布局经过本机只读探测；Intel 保留原有 AppleSmartBattery 电压、电流回退。

输入传感器缺失时，使用 AppleSmartBattery 的 `PowerTelemetryData.SystemPowerIn`，将 mW 转为 W；电池电压、电流始终来自同一采样来源。基础电池详情继续读取额定功率、循环次数和剩余时间。功率开关关闭后不读取对应新增 SMC 传感器；所有功率关闭时保留原有 15 秒详情刷新，不额外进行快速采样。

适配器额定功率只是能力上限，绝不作为实际输入的替代。所有值都是系统遥测的估算，不是插座侧功率；不同传感器更新时刻不同，三项功率可能不完全相加。未知显示“暂不可用”，不补成 0 W。电源状态不匹配、早于电源切换、过期或未来异常的样本会被丢弃。电池供电时保留原来的净放电功率详情。

接电时，左侧为充电器，右侧为电池与系统。流带共用一个瓦数比例，基准为输入与可见输出合计的较大者。隐藏一个输出后，剩余支路仍按同一比例表示功率；0 W 与未知输入/输出不绘制有厚度的流带。不会为了让图形守恒而改写测量值。

打开电池面板且有功率选项开启时每 2 秒读取，关闭面板即停止。部分机型只能回退到较慢的系统电池遥测，即使重新读取，也可能约一分钟才产生新样本。图形为静态 SwiftUI 路径，无常驻动画。

## 高能耗应用的口径

开启且电池面板打开时，每 5 秒读取当前用户有权限访问的进程累计计数；首个样本只建立基线。使用 `proc_pid_rusage` 的 CPU 能耗计数增量排序。旧内核不支持该计数，或可比较进程的能耗覆盖不完整时，整体切换为 CPU 活跃度估算，并明确显示说明；不将两种量纲混排。

同一应用包内的辅助进程归到外层应用，PID 复用、计数回退、过长采样间隔不会产生虚假峰值。列表不包含无法读取的进程，也不代表完整 GPU、ANE、系统进程或所有外置辅助进程的能耗。关闭选项或面板即清空基线、取消周期工作并丢弃迟到结果；阻塞读取时旧名单也会过期。

不启动 `powermetrics`，不申请 root、不扩展 Helper，不读取应用内容、命令行或文档。

数据口径依据：[Apple XNU Recount](https://github.com/apple-oss-distributions/xnu/blob/main/doc/observability/recount.md) 将该计数定义为 CPU 纳焦能量；[Apple 的适配器详情 API](https://developer.apple.com/documentation/iokit/1523866-iopscopyexternalpoweradapterdeta) 提供适配器属性。SMC 键用途另对照 [Stats 的电池读取实现](https://github.com/exelban/stats/blob/master/Modules/Battery/readers.swift)。
