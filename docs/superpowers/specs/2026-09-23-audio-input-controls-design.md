# 状态面板声音输入设备与控制设计

## 目标与已确认的边界

用户希望在 Status Trio 的**现有状态面板**里新增独立的「声音输入」项，快速查看并切换系统默认麦克风，同时调整当前麦克风的输入音量、切换其原生静音状态。该项在新安装和既有安装中都**默认关闭**，可在「设置 → 状态面板」中开启和排序。现有声音输出项保持原样；不新增菜单栏图标或独立 App。

成功标准：用户开启后，面板显示与系统默认输入一致的设备，选择另一台设备后系统「声音 → 输入」同步变化；从系统或其他 App 修改默认设备、设备热插拔时，面板也更新。只有硬件提供可读且可写的输入音量/静音控制时才允许操作。切换和控制失败不能在 UI 中伪装成成功。

参考资料：`/Users/lingsmbp/Documents/github/macos-input-source-switcher.md` 展示了 Core Audio HAL 的设备枚举、默认输入读写和监听思路，但其中的独立 `MenuBarExtra`、单例管理器、演示代码和「无需权限」结论**不是本项目的实现指令或验收依据**。本设计沿用 Status Trio 已有的监控、注入、设置和弹窗架构；具体权限行为仍需在实机验证。

## 用户界面与设置

- `PopupSection` 增加独立的声音输入项，附麦克风图标和本地化名称；追加到既有默认排序末尾，不改变既有项目顺序。`SettingsStore.defaultEnabledPopupSections` 不包含新项；既有的 `popupSectionOrder` 和 `enabledPopupSections` 持久化数据在反序列化时也应补全排序、保持新项关闭。启用/禁用立即接通/停止输入监控。
- 面板顶部显示「声音输入」及当前默认设备名称，并提供打开系统声音设置的齿轮；下方显示输入静音按钮和 0–100% 输入音量滑块，最后显示设备列表。列表即使只有一台设备也可见；当前设备排首位，其余按本地化设备名排序，当前项有对勾和无障碍值。点击另一行发起系统默认输入切换，不关闭面板。
- 当前默认输入不存在时顶部显示「无默认输入设备」，不显示虚构的音量值；若列表仍有可选设备，允许从列表选择。仅当列表也为空时显示「无可用输入设备」。设备不提供**可读且可写**的音量或静音属性时，对应控件保持可见但禁用，提供明确的帮助文本及无障碍说明；两项能力分别判断。
- 音量百分比表示设备输入增益的标量，不是实时声音电平。调节音量不自动解除静音。选择设备不改变它原有的输入增益或静音状态；新设备的控件值必须重新读取。
- 新增的名称、空状态、不可用原因、操作失败提示及无障碍文案覆盖项目现有的 12 种语言。首版不加自定义输入设备排序、显示数量限制、全局快捷键、录音、电平表、音频效果或退出时还原设备。

## 架构与职责

采用**独立输入链路**，不把输入数据和命令塞进现有输出 `VolumeStatus` / `VolumeMonitor`。

1. **HAL 适配层**：新增可替换的输入设备读取与命令接口。系统实现使用 Core Audio 的默认输入、设备列表、输入作用域的流/通道、标量音量、静音以及属性可写性检查；优先使用设备主元素，必要时回退到输入通道元素。只纳入有效、未隐藏、有输入流并可作为默认输入的设备；用运行时设备 ID 发送命令；有稳定 UID 时用于跨枚举识别，UID 缺失时只在当次快照使用设备 ID，不持久化所选设备。调用前再次检查设备仍有效且能力可用。
2. **`AudioInputMonitor`**：提供 `AudioInputStatus`（设备列表、默认设备 ID、当前设备名、可选音量值、音量/静音能力、静音状态、刷新/操作错误）。在启用时注册系统设备列表与默认输入变化监听，并监听当前设备的输入音量与静音属性；默认设备更换时移除旧设备监听、添加新设备监听，禁用/退出时全部移除。来自 HAL 回调的变化经后台读取、合并刷新后发布到主 actor。监听闭包生命周期与注册/移除必须配对，不照搬参考文档的全局单例和缺少清理的示例。
3. **应用集成**：`AppEnvironment` 创建并注入新监控；`SystemStatusStore` 对外暴露独立的 `liveInput` 和选择/音量/静音命令，驱动启用状态、面板可见性、唤醒恢复与关闭清理。该状态不进入菜单栏/Dock 图标所用的 `StatusSnapshot`，避免改变输出图标或在关闭输入项时承担采集开销。`StatusPopoverView` 用单独的输入视图呈现它，设置里的分项开关沿用现有排序 UI。
4. **刷新策略**：默认关闭时不注册输入监听、不枚举设备、不轮询。开启但面板关闭时可保留轻量事件监听，仅标记列表过期；面板打开时后台读取完整快照，期间显示刷新态，之后根据变化事件更新。无需高频输入电平采样；后台读取和命令不能阻塞 SwiftUI/主 actor。延迟返回的旧读取通过代次或等价机制丢弃，避免覆盖较新的系统状态。

### 多通道控制的明确规则

- 输入音量：优先使用主元素，前提是可读且可写；否则仅当所有相关输入通道都有可读且可写的音量属性时，展示其标量平均值，设置时对这些通道写入相同的 0–1 标量。缺一不可时禁用滑块。若写入部分成功，报告失败并立即读取实际值，不宣称已经设置到目标百分比。
- 输入静音：同样优先使用可读且可写的主元素，否则要求所有相关输入通道都可读且可写。通道状态不一致时呈现「部分静音」状态，首次点击统一设为静音；全静音时点击解除全部静音，其余情况下点击设为全部静音。部分写入失败要显示失败并刷新实际状态。**绝不通过把音量设为 0 模拟静音。**
- 设备驱动不报告能力、读值无效，或命令时能力消失时，按不支持/失败处理；不以 0 代替未知输入音量。

## 失败、并发与权限

- 用户操作期间可以展示忙碌状态；滑块允许本地拖动草稿，但**不提前改变选中标记、静音状态或已确认的音量值**。命令返回后读取实际系统状态；返回错误、设备消失、读回不符或超时，显示短暂的本地化错误（约 4 秒），保留/恢复实际状态。下一次成功或新动作清除旧错误；设备热插拔和其他 App 的修改始终以系统状态为准。
- 对连续拖动滑块合并/覆盖尚未发送的目标值，限制并发写入；命令和监听触发的旧回调不得覆盖较新的意图或刷新。组件停用后不发布回调，也不继续访问已撤销监听的设备。
- 本功能仅修改路由及设备控制属性，**不打开输入流读取音频样本**，不主动请求麦克风采集权限、不增加录音用途描述或音频采集 entitlement。不要把参考文档中的「零权限」当成跨系统版本与所有设备的保证；以实机首启、沙箱/分发环境及系统隐私指示器验证为准。仓库当前 Ad-hoc 分发的签名限制与此功能分开记录。

## 验证

- **自动测试**：默认开关和旧设置迁移；分项排序/可见性；无设备、单设备、多设备、隐藏/无输入/不可默认设备过滤；主元素/多通道能力矩阵、部分静音与部分写入失败；外部默认设备变化、插拔、停用监听；命令失败/超时、过期读取丢弃、关闭后不再枚举；UI 禁用说明及无障碍文本。通过注入的 HAL 假实现测试，不依赖真实麦克风。
- **本机人工验证**：内建麦克风与一台可插拔输入设备相互切换；面板与系统「声音 → 输入」双向同步；插拔及睡眠唤醒；不支持输入音量/静音的设备控件禁用；切换/写入失败可见；开启和关闭该项后监听/刷新负担符合预期；无录音采集、意外的 TCC 弹窗或麦克风使用指示。无法取得某类设备时在测试报告里写明未验证，不虚报通过。
- **工程门槛**：实现阶段运行 `swift test`、`swift build -c release`；由于改动涉及 `@MainActor`/SwiftUI 绑定，合并或发布前再用仓库指定的 Xcode 26.6 / Swift 6.3.3 运行一次 `publish=false` release workflow。若 GitHub Actions 失败，按仓库规则记录到 `docs/swift-ci-compatibility.md`。spec 提交本身不构成实现或发布批准。
