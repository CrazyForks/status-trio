# 状态面板显示开关设计

## 目标

允许用户选择哪些状态项目显示在状态面板中。现有排序偏好继续保留，但排序和显示开关成为两个相互独立的能力。

## 默认值与迁移

- 电量、网络和音量默认开启。
- 蓝牙默认关闭。
- 全新安装时，状态面板默认显示电量、网络和音量。
- 已有用户如果尚未保存过显示开关，也采用以上默认值。
- 已有状态面板排序保持不变。关闭的项目继续保留在设置列表中的原位置，重新开启后回到原来的顺序位置。
- 持久化数据中的未知项目标识会被忽略。

## 设置界面

新增一个独立的“状态面板”设置 Tab，用于管理状态面板内容。用户可见文案统一使用“状态面板”，不再使用容易与 alert/dialog 混淆的“弹窗”。

- 新 Tab 放在“基础”之后，英文名称为 `Status Panel`，简体中文为“状态面板”，繁体中文为“狀態面板”。
- 原“基础”Tab 中的 Popup 排序区域移除。
- 新 Tab 内使用“显示项目”作为分区标题。
- 说明文案为“选择状态面板显示的项目，并拖动调整顺序。”

- 每一行包含复选框样式的显示开关、项目图标和名称，以及现有的拖拽手柄。
- 修改开关后立即更新状态面板显示状态并持久化。
- 拖拽仍然只调整所有项目的完整顺序，包括当前关闭的项目。
- 这些设置只影响状态面板，不改变菜单栏图标行为，也不改变电量、网络和音量监控器的可用性。

设置窗口需要继续使用新建 Tab 的生命周期机制，确保首次切到“状态面板”时才构建对应 SwiftUI 内容。

## 状态面板渲染

状态面板根据保存的顺序过滤出已开启的项目进行渲染。

- 分隔线只插入到可见项目之间。
- 因为蓝牙默认关闭，所以初始状态面板中不会显示蓝牙。
- 网络保持现有默认行为和权限流程。选择网络权限操作时，仍然按照现有方式申请定位权限。

## 蓝牙权限流程

蓝牙继续采用延迟启动策略：App 启动时不会创建 `CBCentralManager`。

- 在设置中开启蓝牙，是第一个允许启动 `BluetoothDeviceController` 并触发 macOS 蓝牙权限弹窗的操作。
- 设置窗口会先激活 App，再启动 CoreBluetooth，确保系统权限弹窗显示在前台。
- 如果用户拒绝或关闭权限弹窗，App 不会自动关闭该偏好。状态面板中的蓝牙项目继续显示现有的拒绝、受限或重试状态。
- 关闭蓝牙时停止蓝牙监控，并从状态面板中移除蓝牙项目。
- 仅打开状态面板不得启动 CoreBluetooth。

## 数据模型

`SettingsStore` 负责保存已开启的 `PopupSection` 集合。

- 完整顺序继续由 `popupSectionOrder` 保存。
- `visiblePopupSections` 根据已开启集合过滤 `popupSectionOrder`。
- `setPopupSection(_:enabled:)` 更新并持久化显示开关。
- 未保存过显示开关时，使用默认集合：电量、网络和音量。

`SystemStatusStore` 向设置界面提供蓝牙生命周期方法：

- 开启时启动蓝牙监控并申请权限。
- 关闭时停止蓝牙监控。

“状态面板”设置界面通过 `SettingsDetailView` 获得 `StatusStore`，在蓝牙开关变化时调用这些方法；其他三个开关只更新 `SettingsStore`。

## 测试

- 设置测试覆盖默认值、持久化、数据清理，以及在不改变顺序的情况下按显示开关过滤。
- 设置 Tab 测试覆盖新增“状态面板”的标识、标题和图标映射。
- 蓝牙时序测试验证：仅打开状态面板不启动 CoreBluetooth；开启蓝牙会启动；关闭蓝牙会停止。
- 现有全部语言本地化测试必须通过。
- 运行 `swift test` 和 `swift build -c release`。
- 因为改动涉及 `@MainActor`、SwiftUI 绑定和 CoreBluetooth 生命周期，必须运行一次 `publish=false` 的 release workflow 预检。

## 不在本次范围内

- 修改菜单栏图标显示开关。
- 增加或删除 `PopupSection` 类型。
- 在用户开启蓝牙项目之前申请蓝牙权限。
