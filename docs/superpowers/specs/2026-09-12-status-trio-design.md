## 1. 背景与目标

Status Trio 是一个仅供个人使用、常驻 macOS 菜单栏的状态工具。它把电池容量、Wi‑Fi 状态和音量状态组合进一个 20 pt 图标中，并在左键弹层和右键菜单中提供少量交互。

第一版的目标是完整跑通以下链路：

1. 从公开系统框架读取电池、Wi‑Fi 和音量状态。
2. 把状态稳定映射为统一的图标参数。
3. 在菜单栏中绘制三合一图标。
4. 按状态更新电池颜色、Wi‑Fi 覆盖层和音量点位。
5. 通过左键弹层与右键菜单提供状态查看和退出能力。

图标基于项目现有的 `status-menubar.svg` 和 `status-menubar-demo.html` 几何与状态设计，不照搬实现方式，而是在原生绘图代码中复刻可缩放矢量结构。

## 2. 第一版范围

### 包含

- 仅菜单栏常驻，不显示 Dock 图标。
- 固定 20 pt 三合一状态图标，在菜单栏标准高度内使用当前确定的最大档位。
- 电池百分比、充电状态和系统低电量模式。
- Wi‑Fi 信号等级、关闭、未关联、无互联网，以及尽力识别的热点、临时连接和互联网共享状态。
- 系统默认输出设备的音量等级与静音状态。
- 左键锚定弹层，展示三项状态、设置占位项和退出。
- 右键或 Control-click 原生菜单，展示版本号、设置占位项和退出。
- 事件驱动更新，5 秒定时校验兜底。
- 单元测试、绘制测试和面向真实系统状态的集成验证。

### 不包含

- 打开或控制 macOS 系统控制中心。
- 完整设置界面和设置持久化。
- 开机自动启动。
- 自定义颜色、图标大小、刷新频率或显示项。
- Wi‑Fi 网络名称、热点名称或其他需要定位权限的信息。
- 网络开关、音量滑杆等系统控制能力。
- Mac App Store 分发、沙盒和 App Store 审核适配。

### 后续扩展边界

未来设置界面作为独立模块接入，用于开机启动、颜色、图标大小和刷新策略。第一版不创建设置界面，也不提前写入偏好数据。

## 3. 用户体验

### 菜单栏图标

- 状态项只显示图标，不显示文字。
- 图标视觉尺寸为 20 pt，绘制时保留 120 × 120 的原始几何坐标系并按比例缩放。
- 普通状态跟随菜单栏明暗外观。
- 充电时电池填充为绿色；系统低电量模式开启时电池填充为黄色；其他情况下使用菜单栏前景色。
- 左键点击、右键点击和 Control-click 都在同一状态项上响应，不改变图标位置。

### 左键弹层

左键切换一个锚定到状态项的 `NSPopover`。点击弹层外部或按 Esc 关闭。

弹层内容固定为：

1. 电池：百分比；副标题显示“正在充电”“低电量模式”或“无电池设备”。
2. Wi‑Fi：格数或特殊状态；副标题显示“已连接”“未关联”“无互联网”“iPhone 热点”“临时连接”“正在共享”等状态。
3. 音量：百分比和 0–4 格；副标题显示当前默认输出设备名称。
4. 设置占位项：显示为“设置… · 即将推出”，不可点击。
5. 退出：显示“退出 Status Trio”。

### 右键菜单

右键或 Control-click 显示原生菜单，内容依次为：

1. `Status Trio 1.0.0`，不可点击。
2. `设置…`，不可点击并标注“即将推出”。
3. 分隔线。
4. `退出 Status Trio`。

右键菜单与左键弹层互斥；打开一个时关闭另一个。应用只有一个实例，退出菜单关闭整个应用。

## 4. 状态模型与视觉映射

### 4.1 电池

数据来源为 IOKit/IOPS。百分比按四舍五入显示为 0–100 的整数。

- 正常：电池弧使用菜单栏前景色。
- 充电：电池填充使用绿色 `#34C759`。
- 系统低电量模式：电池填充使用黄色 `#F2B900`。
- 充电和低电量模式同时发生时，充电绿色优先。
- 无电池设备：按满电处理，显示 100%，弹层副标题显示“无电池设备”。
- 电池轨道使用与前景色相同颜色，并保持 22% 透明度。
- 电池弧从原 SVG 的起点沿现有路径方向增长，`pathLength` 映射为 100。

### 4.2 Wi‑Fi

数据来源为 CoreWLAN 和 `NWPathMonitor`，均使用公开 API；无法可靠分类时回退普通状态。互联网共享另以未公开的动态存储键 `com.apple.nat` 做尽力增强，不承诺可用性或稳定性；该键缺失、不可读或值不确定时安全回退，不猜测共享状态。

已连接信号按 RSSI 映射：

| RSSI | 格数 |
| --- | --- |
| `>= -55 dBm` | 3 |
| `-70 ... -56 dBm` | 2 |
| `-85 ... -71 dBm` | 1 |
| `< -85 dBm` | 0 |

状态与图标映射：

- 已连接：按 RSSI 显示 1–3 层 Wi‑Fi 弧和中心点，0 格时全部弱化。
- 未关联：显示三条弧和中心点，全部使用 30% 前景色。
- 关闭或不可用：显示 30% 前景色的完整 Wi‑Fi，并叠加斜线。
- 无互联网：显示灰色感叹号并隐藏中心点。
- 临时连接：使用现有临时连接覆盖层；优先由 IBSS 接口模式识别。
- iPhone 热点：使用现有热点覆盖层；在 Wi‑Fi 路径为 expensive 且符合热点特征时尽力识别。
- 互联网共享：使用现有共享覆盖层；仅在尽力读取未公开的 `com.apple.nat` 动态存储键并明确得到启用状态时识别。该探针不是公开 API，失败时按普通状态回退。
- 特殊状态判断顺序为：关闭、未关联、互联网共享、临时连接、iPhone 热点、无互联网、普通已连接。
- 任意特殊状态无法可靠确认时，按普通已连接或未关联状态显示，不显示猜测图标。

### 4.3 音量

数据来源为 CoreAudio 默认输出设备的 volume scalar 与 mute 属性。

- 静音或音量 0：0 格，四个点全部弱化。
- `0 < volume <= 25%`：1 格。
- `25% < volume <= 50%`：2 格。
- `50% < volume <= 75%`：3 格。
- `75% < volume <= 100%`：4 格。
- 无默认输出设备：数值显示 `—`，四个点全部弱化，不显示为静音。

### 4.4 快照一致性

三类状态组成一个不可变 `StatusSnapshot`。`SystemStatusStore` 每次只在主线程发布完整快照，图标和弹层读取同一版本，避免三个区域出现不同步状态。

## 5. 架构

### 5.1 组件

- `AppDelegate`：管理应用生命周期、单实例行为和主控制器。
- `StatusBarController`：创建 `NSStatusItem`，处理左右键事件，管理 `NSPopover` 与右键 `NSMenu`。
- `SystemStatusStore`：接收监控更新、合并为 `StatusSnapshot`，在主线程发布。
- `BatteryMonitor`：读取并监听电池百分比、充电状态和低电量模式。
- `WiFiMonitor`：读取并监听 CoreWLAN 和网络可达性状态。
- `VolumeMonitor`：读取并监听默认输出设备、音量和静音状态。
- `StatusIconRenderer`：把 `StatusSnapshot` 绘制为 20 pt `NSImage`，不读取系统状态，并响应菜单栏外观变化。
- `StatusPopoverView`：SwiftUI 只读弹层。
- `StatusMenuBuilder`：构造原生右键菜单。

### 5.2 技术基线

- 使用 Swift Package Manager、Swift 6 和 AppKit 生命周期构建 macOS App；`Package.swift` 可直接使用 Xcode 打开。
- Deployment Target 为 macOS 15，当前开发环境为 macOS 27、Apple Silicon。
- `Info.plist` 设置 `LSUIElement = true`，应用只显示菜单栏状态项。
- 不启用 App Sandbox，不申请网络、定位或其他隐私权限。
- 第一版界面文案使用简体中文。

### 5.3 数据流

```text
IOPS / CoreWLAN / NWPathMonitor / CoreAudio
                    |
                    v
      Battery / WiFi / Volume Monitors
                    |
                    v
             SystemStatusStore
                    |
                    v
              StatusSnapshot
               /            \
              v              v
   StatusIconRenderer   Popover / Menu UI
```

所有系统监控通过独立协议注入，使 `SystemStatusStore`、图标渲染和 UI 可以在测试中使用假数据源，不直接依赖真实硬件。

### 5.4 并发与线程

- 系统回调进入各监控自己的串行队列。
- 监控通过 `AsyncStream` 向 `SystemStatusStore` 发送 `Sendable` 状态值。
- `SystemStatusStore` 使用 `@MainActor` 发布最终快照。
- 相同连续状态会被合并，不触发重复重绘。
- 监控停止时取消监听、定时器和 `AsyncStream` continuation，避免应用退出后残留回调。

## 6. 刷新与监听策略

采用事件驱动为主、5 秒定时校验兜底。

- 电池：监听 IOPS 变化和系统低电量模式通知。
- Wi‑Fi：监听 CoreWLAN 的电源、链路、SSID/BSSID、信号质量和模式变化；`NWPathMonitor` 负责互联网可达性。
- 音量：监听默认输出设备、volume scalar 和 mute 的 CoreAudio 属性变化。
- 兜底刷新每 5 秒读取一次三个数据源；如果最近事件已提供相同值，不发布新快照。
- 系统休眠后恢复时立即执行一次全量刷新，并重新建立失效的事件监听。

## 7. 图标绘制

- 绘制单位为 20 pt，输出使用 Retina 像素密度。
- 几何取自现有 SVG：外圈电池弧、三层 Wi‑Fi 信号、中心点、特殊覆盖层、四个音量点。
- 电池轨道和填充使用同一路径，填充通过路径进度控制。
- Wi‑Fi 使用独立图层以便单独弱化、隐藏或叠加特殊符号。
- 音量四个点保持原位置，按等级控制可见度。
- 菜单栏外观变化时重新解析前景色并渲染图像，确保浅色和深色模式都清晰。
- 由于普通状态需要跟随菜单栏颜色、特殊状态需要绿色和黄色，图标不使用系统模板图片。
- 绘制代码拆为几何构建和状态应用两层；测试可以直接验证每一层的输出。

## 8. 错误处理与降级

- 无电池：按满电处理并标注“无电池设备”。
- 无默认音频输出：音量显示 `—`，音量点全部弱化。
- Wi‑Fi 查询失败或事件流中断：保留最近有效状态最多 30 秒，之后显示弱化不可用态并自动重建监听。
- 单个监控失败不影响其他监控，`SystemStatusStore` 仍可发布其余有效状态。
- 无法区分的 Wi‑Fi 特殊状态不猜测，退回稳定的普通状态。
- 系统休眠唤醒导致监听失效时，以一次全量刷新和重新注册监听恢复。
- 使用 `os.Logger` 按模块记录异常；正常运行不输出高频日志。

## 9. 测试

### 单元测试

- 电池百分比取整、充电优先级和无电池回退。
- RSSI 边界值到 0–3 格的映射。
- 音量边界值与静音、无输出设备映射。
- Wi‑Fi 特殊状态分类优先级和回退逻辑。
- `SystemStatusStore` 的快照合并、去重和主线程发布。
- 使用假监控验证监控失败时其他状态不受影响。

### 绘制测试

- 为普通、充电、低电量模式、无电池、Wi‑Fi 各状态和音量 0–4 格生成确定性图像。
- 验证浅色与深色菜单栏下前景色解析正确。
- 验证特殊 Wi‑Fi 覆盖层不会意外覆盖电池和音量区域。

### 集成验证

- 浅色和深色菜单栏。
- 电池充放电、充电完成、低电量模式和低电量模式关闭。
- Wi‑Fi 关闭、未关联、已连接、RSSI 变化和无互联网。
- 临时网络、iPhone 热点和互联网共享的尽力识别与回退。
- 音量调整、静音、切换默认输出设备。
- 左键弹层、右键菜单、点击外部、Esc 和退出。
- 系统休眠唤醒后的自动恢复。

## 10. 验收标准

第一版完成时必须满足：

1. 启动后仅出现菜单栏图标，不显示 Dock 图标。
2. 图标在浅色和深色菜单栏中均清晰可辨。
3. 电池、Wi‑Fi 和音量变化在 1 秒内反映到图标，5 秒兜底刷新运行正常。
4. 左键弹层锚定在状态项下方，右键菜单位置符合系统惯例。
5. 充电、低电量模式、无电池、Wi‑Fi 特殊状态和音量分档均符合本规格。
6. 单个数据源失败不会导致应用退出或其他状态消失。
7. 单元测试、绘制测试和手动集成验证全部通过。
8. 应用无沙盒、无网络权限、无定位权限，仅使用本地系统状态 API。
